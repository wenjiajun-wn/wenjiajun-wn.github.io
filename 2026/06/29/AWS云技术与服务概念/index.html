AWS云技术与服务概念

2026年06月29日 · AWS

AWS 云技术：从计算、存储到 AI

云计算的世界很大，AWS 提供的服务也很多。想在短时间内学习 AWS 核心服务的整体认知，从计算、数据库、网络存储，一路到 AI/ML，是一条很实用的学习路径。

一、计算服务：从 EC2 到无服务器

EC2：云上最基础的计算单元

Amazon EC2（Elastic Compute Cloud）提供的是可伸缩的云端计算能力，每一台虚拟机被称为一个”实例”。它的核心特点是可以根据需求灵活地扩容或缩容，并且提供多种针对不同场景优化的实例类型。AWS 把 EC2 实例分成六大类：

  • 通用型：兼顾计算、内存与网络资源的均衡配置，适合动态网站、代码仓库等场景。
  • 计算优化型：面向计算密集型的高性能工作负载，比如科学模拟、金融建模。
  • 内存优化型：适合内存消耗大但存储需求不高的场景，比如实时流数据分析、字幕生成。
  • 存储优化型：擅长对大数据集进行高吞吐的顺序读写，常用于数据仓库、大型关系型数据库重构。
  • 加速计算型：搭载 GPU、FPGA 等专用硬件加速器，适合深度学习、游戏图形渲染。
  • 高性能计算（HPC）优化型：在大规模高性能工作负载上追求最佳性价比，用于天气预测、碰撞模拟等场景。

连接 EC2 实例的方式也有好几种：通过 SSH 客户端用密钥连接（需要自行管理密钥）、通过 AWS Session Manager 实现无密钥的、与 IAM 集成的访问，或者用 EC2 Instance Connect 做基于浏览器的临时快速连接。

负载均衡与自动扩缩容

当流量增大时，靠一台实例显然扛不住。负载均衡的作用是把进来的请求均匀分配到多个 EC2 实例上，避免单点过载，同时保证高可用性和水平扩展能力。它的工作流程是：用户请求先到达负载均衡器，负载均衡器优先把流量导向主目标组；如果需求继续上升，再激活备用目标组，把负载分散到所有实例上。

弹性（Elasticity）则是指系统能够根据需求自动伸缩资源的能力，这在 EC2 上是通过 Auto Scaling 实现的：系统会根据实际使用情况自动增减活跃实例数量，从而优化成本、避免资源过度配置。简单说，负载均衡负责”把流量分匀”，自动扩缩容负责”按需增减机器”——二者经常配合使用，但解决的是不同的问题。

容器与无服务器计算

随着微服务架构和事件驱动应用的普及，传统的常驻计算模式已经不够用了。容器把应用程序及其依赖打包成轻量的独立单元，既能与底层系统解耦，又能共享宿主操作系统资源，还便于跨环境迁移。AWS 提供两个主要的容器服务：

  • Amazon ECS：全托管的容器编排服务，适合部署和管理微服务应用，也能用来做批处理任务的调度和运行。
  • Amazon EKS：专注于运行基于 Kubernetes 的容器编排服务，常与加速计算型 EC2 实例搭配运行机器学习容器，也适合管理混合云环境下的集群。

而无服务器架构则更进一步：完全不需要管理服务器，由事件触发函数执行，并且只为实际用量付费。AWS Lambda 是这一领域的代表，可以在响应事件时自动运行代码并弹性伸缩计算资源。AWS Fargate 则为容器提供无服务器化的运行环境，常用于无需大量服务器预置的 AI/ML 应用，以及需要并行处理能力的大规模批处理任务。

二、数据库、网络与存储：AWS 的数据基础

数据库服务

AWS 的数据库服务让用户无需自建物理基础设施或安装软件就能直接使用数据库。按数据模型划分，主要有三类：

关系型数据库将数据组织成带有预定义关系的表结构，优势在于数据完整性、一致性与可扩展性。AWS 在这方面提供：

  • Amazon RDS：全托管关系型数据库服务，支持多种数据库引擎，可高效扩展云端及本地数据库。
  • AWS Aurora：针对 MySQL 和 PostgreSQL 优化的关系型数据库，性能出众且成本仅为传统方案的约十分之一，内置持续备份和跨区域自动复制。

NoSQL 数据库用于处理 JSON、文档等超出传统关系模型的多样化数据，具备模式灵活性和水平扩展能力。代表服务是 Amazon DynamoDB——一款无服务器、全托管的 NoSQL 数据库，能在任意规模下实现个位数毫秒级的响应性能，可用吞吐几乎不受限，并提供 99.999% 的全球可用性，常用于实时视频流媒体、购物车追踪、游戏玩家数据和排行榜等场景。此外，Amazon DocumentDB 是兼容 MongoDB 的原生 JSON 文档数据库，适合内容管理系统、用户画像管理，乃至语义搜索、产品推荐、聊天机器人等生成式 AI 场景。

内存数据库利用 RAM 实现高性能的数据存取，适合缓存高频访问数据、实时分析和高速事务处理。MemoryDB for Redis 就是 AWS 在这一领域的方案，具备超高速读写、99.99% 可用性以及近乎零数据丢失的快速恢复能力。

值得一提的是，除了这些全托管方案，用户也可以选择在 EC2 实例上自行部署数据库，这种方式能提供更细粒度的配置控制，但备份和补丁维护的责任也完全落在用户自己身上。

数据库迁移

面对遗留系统难以满足快速扩展需求，以及生成式 AI 对算力和存储提出的更高要求，数据迁移成为许多企业绕不开的课题。AWS 提供了一套迁移工具组合：

  • AWS Database Migration Service：支持 20 多种数据库和分析引擎的迁移，通过自动化实时数据复制将停机时间降到最低，并提供校验检查和任务监控。
  • AWS Snow Family：提供物理设备，用于 PB 级数据的离线传输，适合边缘场景下的大规模数据搬迁。
  • AWS DataSync：通过并行处理简化、自动化并加速本地存储与 AWS 云之间的大数据量传输。
  • AWS Schema Conversion Tool：自动将源数据库的模式转换为目标格式，支持自定义转换规则，并提供诊断与优化建议。

网络服务

Amazon VPC（Virtual Private Cloud）是 AWS 云中一个逻辑隔离的网络空间，用户可以在其中启动和管理自己的资源。它支持 IPv4 和 IPv6、可自定义 IP 地址范围，并通过安全组和网络访问控制列表（ACL）提供多层安全防护，同时允许用户完全掌控子网、路由表和网关配置。AWS 会自动创建一个默认 VPC（带有预配置的子网和默认联网能力），用户也可以创建完全自定义的 VPC。

在网络安全层面，网络 ACL 相当于子网级别的防火墙，安全组则是实例级别的防火墙。而 VPC 终端节点和 AWS PrivateLink 能够让 AWS 服务之间、乃至与本地网络之间实现私有连接，无需暴露公网 IP。至于连接本地网络与云端的方式，AWS VPN 适合小规模或临时性连接场景，AWS Direct Connect 则提供专线连接，拥有更高带宽和更低延迟，适合关键业务的持续性负载。

此外，Amazon Route 53 作为 DNS 服务负责把域名解析为 IP 地址，而 Amazon CloudFront 作为内容分发网络（CDN），通过在全球部署缓存节点来加速网页内容、API 与流媒体的传输，同时提供 DDoS 防护和 HTTPS 支持。

存储解决方案

AWS 的存储服务大致可以分为四类：

  • 对象存储：以”对象”为单位管理非结构化数据，支持水平扩展和元数据管理。Amazon S3 是这一领域的旗舰产品，提供 99.999999999%（11 个 9）的数据持久性，并覆盖所有 AWS 区域。S3 还细分出多种存储类别：Standard（高频访问）、Intelligent-Tiering（自动根据访问模式切换层级以优化成本）、One Zone-IA（单可用区、低成本，适合易于重建的低频数据）、Glacier（低成本归档，检索时间从几分钟到几小时不等）、Glacier Deep Archive（最低成本、检索时间最长）以及 S3 Outposts（本地存储延伸，打通私有云与公有云数据）。
  • 块存储：把数据切分成带有唯一地址的固定大小数据块，适合高 I/O 事务型应用和大数据分析引擎。Amazon EBS 是专为配合 AWS 计算服务设计的高性能块存储方案。
  • 文件存储：以分层结构组织数据，支持多用户多服务的并发读写。Amazon EFS 适用于简化 DevOps 流程、增强内容管理系统性能，以及加速数据科学工作。
  • 缓存存储：把高频访问数据放在能快速取用的位置，借此提升应用响应速度、降低后端负载。Amazon ElastiCache 常用于存储 Web 应用的会话数据，以及加速实时分析数据的访问。

最后，存储生命周期策略能基于预定义规则自动在 S3 各存储类别之间迁移对象，兼顾成本与性能优化；而 AWS Backup 则是一项全托管的集中式备份服务，支持跨区域备份并可以设定保留和删除策略。

三、AI 与机器学习

在前两部分打好计算与数据基础之后，AWS 在 AI/ML 领域构建了一整套从”开箱即用”到”完全自定义”的服务体系。要理解这套体系，得先厘清两个常被混用的概念：人工智能（AI）是一个更宽泛的概念，指的是让机器模拟人类智能的各种方法，涵盖问题解决、语音识别、学习能力等多个方面；机器学习（ML）则是 AI 的一个子集，专注于让系统通过海量数据自主学习规律、推导结论，而不是靠人工写死的规则。AWS 把这块业务分成了四类：AI 服务、ML 服务、ML 框架与基础设施，以及一套通用的机器学习工作流程。

AI 服务

AWS 的 AI 类服务大多是预训练或自动训练好的模型，开发者不需要懂太多机器学习原理，直接调用接口就能把智能能力集成进自己的应用里。常见的几个包括：

  • Amazon Translate：多语言文本自动翻译。
  • Amazon Polly：文本转语音，输出接近真人的语音效果。
  • Amazon Lex：用于搭建聊天机器人一类的对话式交互界面，处理从开发到部署的整个流程。
  • Amazon Comprehend：文本分析工具，可以提取情感倾向、识别实体，或判断文本所使用的语言。
  • Amazon Forecast：基于历史数据自动生成时间序列预测。
  • Amazon CodeGuru：面向开发者的自动化代码审查工具，能给出提升代码质量的智能建议。
  • Amazon Rekognition：图像和视频识别服务，可以识别物体、提取情绪等信息。

这些服务的共同特点是”黑盒可用”——不需要关心背后的模型是怎么训练出来的，重点是解决业务问题。

ML 服务

如果 AI 服务提供的是现成的智能，那么 ML 服务面向的就是自己动手构建定制化模型的开发者和数据科学家。AWS 在这方面主要提供两个服务：

  • Amazon SageMaker：一个覆盖机器学习全生命周期的托管服务，集成了 Jupyter Notebook，支持快速训练和部署模型，可以用来做预测分析、计算机视觉、自然语言处理等各类应用。
  • Amazon CodeWhisperer：由机器学习驱动的代码审查工具，能自动化、简化整个代码审查流程，提升代码质量。

ML 框架

除了托管服务，AWS 也支持业界主流的开源机器学习框架运行在其基础设施之上，方便团队按需搭建可扩展、可定制的训练和部署流程。三个代表性框架是：

  • TensorFlow：谷歌开发的开源框架，支持模型的开发、部署与规模化扩展。
  • PyTorch：Meta 打造的深度学习框架，擅长处理基于计算图的动态执行场景。
  • MXNet：由 Apache 管理，专注于大规模、分布式的深度神经网络训练。

这一层的意义在于灵活性：企业不必完全依赖 AWS 的封装服务，也可以把已有的模型训练代码迁移到云端资源上继续跑。

一个典型的机器学习流水线长什么样？

把前面提到的计算、存储、数据库服务和 AI/ML 服务串起来，一个典型的 AWS ML 流水线大致是这样运作的：

  1. 数据存储：原始数据先存放在 S3 存储桶中，作为整个流程的数据源。
  2. 模型训练：SageMaker 直接从 S3 读取数据，完成模型的开发和训练。
  3. 部署上线：训练好的 SageMaker Notebook 被打包成容器，通过 EKS 推送到生产环境。
  4. 自动化再训练：当有新数据到来时，Lambda 会被触发，自动启动模型的重新训练和部署流程，让整个系统保持”自我更新”的能力。

这套流程很好地体现了 AWS 各服务模块之间的协作关系：S3 负责存数据，SageMaker 负责训练，EKS 负责稳定部署，Lambda 负责自动化触发——计算层、数据层与 AI 层在这里真正被打通成一条完整的工程闭环。

总结

把这三大模块串起来看，AWS 的核心服务体系其实遵循着一条清晰的逻辑链：

  • 计算层（EC2、ECS/EKS、Lambda/Fargate）负责”跑起来”——不管是传统虚拟机、容器化微服务，还是完全无服务器的事件驱动应用；
  • 数据与网络层（RDS/Aurora、DynamoDB/DocumentDB、MemoryDB、VPC、S3/EBS/EFS）负责”存得住、传得快、连得通”；
  • AI/ML 层（Translate、Rekognition、SageMaker、TensorFlow/PyTorch/MXNet）则是在前两层稳固的基础设施之上，把数据和算力转化为实际的智能应用——想要快速集成现成能力就用 AI 服务，想要自己训练定制模型就用 SageMaker，想要掌控底层框架就直接跑 TensorFlow/PyTorch/MXNet，想要搭建完整的生产级流水线，就组合使用 S3 + SageMaker + EKS + Lambda。

理解这条逻辑链，再去看 AWS 具体的产品名称和参数，会发现它们并不是孤立的功能点，而是彼此配合、服务于不同业务场景的一整套工具箱。这也正是 AWS 能够支撑起从初创公司到全球企业的各种复杂应用、并在 AI 时代持续领跑的原因所在。
